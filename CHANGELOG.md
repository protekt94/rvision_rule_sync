# История изменений

## 0.4.1 — 22.10.2026

### Изменено

- Для обозначения своих изменений используются `### start` и `### end`. Старые `# start` и `# end` больше не считаются маркерами.
- Добавлена поддержка маркеров внутри `!vrl` и на верхнем уровне YAML. Для YAML из сравнения исключаются целые поля между маркерами.
- Код между маркерами, включая сами маркеры, исключается из хешей, статусов и diff.
- Для сравнения с правилами R-Vision SIEM соответствующий участок определяется по неизменённым строкам до и после маркеров. Если границы не удаётся определить однозначно, правило получает `REVIEW_REQUIRED` и предупреждение в отчёте.
- В отчёт добавлен раздел «Защищённые участки» с содержимым исключённого кода и номерами строк.

### Исправлено

- Из сравнения исключены служебные поля `id`, `rid`, `test`, `tests`, `version`, `author`, `date`, `correlation_rule_version`, а также отдельные присваивания `.correlation_rule_version`, `.normalization_rule_id`, `.normalization_rule_version` внутри VRL.
- Сравнение, хеши и diff используют одну нормализованную версию правила. Исходные `.ro` при этом не изменяются.
- При генерации объединённого правила сохраняются пользовательские служебные присваивания и маркеры на уровне YAML.
- Из `reports/` убрано дублирование исходных правил. Сохраняются отчёты и, при необходимости, сгенерированные правила.

### Проверка

- Добавлено 30 тестов для прямого сравнения, 3-way merge, защищённых участков, некорректных маркеров и сохранения исходного VRL.

### Важно

- В существующих `VI-*.ro` старые маркеры необходимо заменить на `### start` / `### end`.
- `NO_CHANGE` означает отсутствие различий **вне исключённых участков**, а не полное совпадение исходных файлов.
