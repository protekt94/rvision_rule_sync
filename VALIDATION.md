## Что исправлено при проверке кода

- Ошибки CRC, повреждённых TAR/ZIP и неподдерживаемого сжатия преобразуются
  в понятную ошибку CLI; неполный отчёт не публикуется.
- Дубликаты ID проверяются без учёта регистра, чтобы исключить перезапись
  снимков на файловых системах с нечувствительными к регистру именами.
- Изменение vendor в отмеченном критичном блоке требует review, даже если
  OURS совпадает с BASE в этом блоке. Учитывается объединение metadata.
- YAML-алиасы отклоняются до построения дерева; ограничены вложенность
  и размер входного .ro. Реальный пакет успешно читается с этими ограничениями.
- Повреждённый state.json проверяется явно и не приводит к AttributeError.
- Имена пакетов и ключи YAML экранируются в Markdown вне блоков кода.

Для каждого исправления добавлена воспроизводящая его проверка. Также сохранены
проверки игнорирования test/tests, маркеров, независимого merge, конфликтов,
канонизации, ZIP/TAR, traversal, ссылок, повторных запусков и нескольких пакетов.

## Настраиваемый префикс

Префикс custom задаётся через --custom-prefix либо запрашивается в интерактивном
терминале. В скриптах и CI он обязателен; личного значения по умолчанию нет.
Bootstrap сохраняет выбранное значение в schema 2, analyze использует его без
повторного вопроса. Для schema 1 префикс выводится из сохранённых пар custom → RV.
Неоднозначные соответствия отклоняются.

Проверены разные длины и составные префиксы, нормализация завершающего дефиса,
некорректные значения, фильтрация смешанной папки, интерактивный и обычный CLI,
сохранение ID/rid при merge, несовпадение параметра с рабочей папкой и старый state.
Синтетические примеры используют SOC- и CUSTOM-. В локальной приватной копии
ID custom заменён на CUSTOM-; остальные поля и полный пакет оставлены для регрессии.
